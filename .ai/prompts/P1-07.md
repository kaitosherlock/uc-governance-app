## What to build

A grants table, reached as a tab on an asset, with a hook in `src/api/queries.ts`.

**Columns:** principal, principal type, privilege, source, actions.

- **Principal** shows its display name; its type (user, group, service principal) is shown as icon
  **plus** text, never colour or icon alone.
- **Privilege** renders as `label — CODE` with the CODE in monospace, for example
  `Read data — SELECT`. Both parts come from the contract; do not invent labels for codes you do not
  recognise, render the code verbatim with the `UnknownBadge` you already have.
- **Source** is the important one and must be unmistakable at a glance and to a screen reader:
  - Direct — solid outline.
  - Inherited from {kind} `{full_name}` — dashed outline with an arrow, and the parent's name.
  - Unknown — dotted outline.
  Icon plus text in every case. Never colour alone. The parent name is a fully-qualified name, so
  use the same truncation-with-full-accessible-name treatment as `AssetOverview`.
- **Actions** are gated by `allowed_actions`. `allowed: false` renders **disabled with its `reason`
  visible**, tooltip plus `aria-describedby`. When `navigate_to` is present, render a link instead
  of a disabled button — for an inherited grant that link is "View permissions at source" and points
  at the object where the grant actually lives.

**Filters** over principal, privilege and source. Filtering is client-side over the loaded page; say
so rather than implying the server filtered. Clearing filters must be reachable by keyboard.

**The limitation line is mandatory.** `meta.limitations` renders under the table, always, never
collapsed behind a disclosure. The fixture data carries a limitation stating that group membership
could not be loaded, and that sentence must appear verbatim. This is the difference between an
honest tool and a dangerous one: if the app cannot see group membership, it cannot know who is
really reached, and it must say so rather than let the table imply completeness.

**Never** render "Nobody has access", "Secure", "Compliant", or "PII protected". Empty success is
"No grants visible to the application on this object." plus the limitations.

**All four states** with stable layout, reusing `StateViews.tsx`: idle, localized skeleton, mapped
error with `next_steps` and correlation id in a `<details>` and a retry button, success.

All user-visible text goes in `strings.ts`.
