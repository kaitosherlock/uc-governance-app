## What to establish, before writing any feature code

Determine whether databricks-sdk 0.140.0, as installed, exposes a **documented, stable** surface for
data classification — automatic PII detection, sensitivity labelling, or classification results on a
column or table. Use the same static introspection approach P0-08 used: inspect the installed
package, do not construct a client, do not call the network, and do not rely on memory of what the
product offers.

Record what you find either way, naming the exact attributes you checked.

## Then, one of two outcomes

**If a real surface exists**, implement the read path for it, following the shape of the existing
adapters: a Protocol, a fixture implementation, an SDK implementation, DTO mapping that allowlists
fields, and contract-shaped errors. Reads only — classification is an observation, not something
this application should be setting. Report coverage honestly in `meta.limitations`, including
anything the surface does not cover.

**If it does not exist**, do not write a stub, do not invent an endpoint, and do not implement a
heuristic classifier of your own. Instead:

- mark the classification rows in `docs/capability-matrix.md` as `unsupported`, with a one-line
  reason naming what you checked and what was absent — `unsupported` means the platform does not
  offer it, as distinct from `not_implemented`, which means we have not built it yet;
- make the capability registry report it the same way, so `/api/v1/capabilities` tells the truth;
- add a test asserting that the capability is reported as unsupported with a reason, so a later
  change cannot quietly flip it to available without evidence.

A heuristic that guesses which columns are sensitive would be worse than nothing here. A governance
tool that labels a column "PII" on its own authority, and is wrong, causes exactly the false
assurance this application is built to avoid.

## Either way

If tags are being used in practice to carry classification — and this project already has a
`classification` governed tag concept — say so explicitly in the matrix and point at the tags
surface, so a reader understands what the application can and cannot tell them.
