WHAT TO BUILD

1. `frontend/src/api/client.ts` — the ONLY place in the application that calls `fetch`.
   - Prefixes every path with `/api/v1` and fills `API_PATHS` placeholders.
   - URL-encodes `full_name` as a single path segment, so `sales.crm.orders` stays one segment.
   - Parses the JSON envelope and narrows on the `success` discriminant.
   - On `success: false` throws a typed `ApiError` carrying the whole `ErrorResponse`, including
     `code`, `message`, `correlation_id` and any `next_steps` and `errors`.
   - Treats HTTP 202 as a success whose payload is an `Operation` with status `unknown`. It is not
     an error.
   - Accepts and forwards an `AbortSignal`, and turns an abort into a distinguishable
     `AbortError` rather than a generic failure.
   - Sends no authentication header. The platform authenticates the browser.
   - Never retries a mutation. A read may be retried by the caller, never by the client itself.

2. `frontend/src/api/errors.ts`
   `ApiError` class plus a `describeError(error)` helper returning the title, body and suggested
   next steps for a given `ErrorCode`, sourced from `strings.ts`, following
   shared/contracts/error-codes.md. Unknown codes fall back to a generic message and are rendered
   verbatim rather than crashing.

3. `frontend/src/api/queries.ts`
   TanStack Query hooks for the three implemented reads: `useContext()`, `useMe()`,
   `useCapabilities()`. Query keys must be identity-scoped exactly as
   docs/02-architecture.md section 8 requires, so include the actor id, the workspace id and the
   scope in the key. Configure sensible `staleTime`, disable retry for 4xx `ApiError`, and pass the
   query's `AbortSignal` into the client.

4. `frontend/src/app/providers.tsx` — add the `QueryClientProvider` here. Keep the router setup.

5. `frontend/src/mocks/handlers.ts` and `frontend/src/mocks/browser.ts`
