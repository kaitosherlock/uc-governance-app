4. `backend/app/api/errors_handler.py`
   Exception handlers registered on the app that turn `AppError`, FastAPI's
   `RequestValidationError`, and any unhandled `Exception` into the `ErrorResponse` envelope.
   Rules: never return a failure with HTTP 200. Never put a stack trace, a token, or an upstream
   response body into the response. An unhandled exception becomes `INTERNAL_ERROR` with a generic
   message; the detail goes to the log with the correlation id.

5. `backend/app/api/middleware.py`
   - Correlation middleware: read the inbound `X-Request-Id` header if present, otherwise generate
     a uuid4. Store it in a context variable, echo it in the `X-Request-Id` response header, and
     put it in `meta.correlation_id` and in every error body.
   - An origin guard for mutating methods: reject a cross-site POST, PATCH, PUT or DELETE using the
     `Origin` and `Sec-Fetch-Site` headers with `FORBIDDEN_ROLE`. Same-origin and missing-origin
     GETs are unaffected.

6. `backend/app/logging_setup.py`
   Structured JSON logging to stdout, including the correlation id. A redaction filter that drops
   any value matching known secret env var names (`UCGOV_PLAN_HMAC_KEY`, `DATABRICKS_CLIENT_SECRET`,
   `PGPASSWORD`, anything ending in `_TOKEN` or `_SECRET`) and any `Bearer <...>` substring.
   Add a unit test proving a secret placed in a log record does not appear in the emitted line.
