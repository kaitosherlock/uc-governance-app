## Reads

For a table, surface its row filter and its column masks, and for each show: the function that
implements it, the input columns it receives, their types, the function's owner, and the
dependencies the function itself has. Where the SDK does not return a field, say it is unavailable
rather than inventing a default.

**Distinguish centrally applied ABAC from directly attached controls.** A mask that arrives from a
policy is governed somewhere else entirely, and someone trying to change it at the table will
otherwise be confused about why their change does not stick. Say which it is, and for an ABAC-
derived control point at the policy.

## The four plan kinds

`set_row_filter`, `drop_row_filter`, `set_column_mask`, `drop_column_mask`, registered so they
inherit the full lifecycle: HMAC binding, TTL, observed-state hash, revalidation, per-target
outcomes, verification, and `MODE_READ_ONLY` under `connected_readonly`.

Validate before building a plan:

- the object actually supports the control;
- the function exists, the caller can see it, and its **signature matches** the columns being passed
  — argument count, order and data types. A type mismatch here fails at query time for every reader
  of the table, so catch it in validation and name the mismatched argument;
- data-type and compute compatibility as the spec requires.

**Dropping or weakening a filter or mask exposes data that was hidden.** Both drop kinds, and any
set that replaces an existing control, must:

- require typed confirmation;
- state in the preview, in plain language, what becomes visible and to whom, as far as the
  application can determine;
- put everything it cannot determine into `impact.unknown` rather than omitting it. If the app
  cannot enumerate who gains visibility, it must say so rather than imply the change is contained.

Never claim the control was tested against real data. Nothing here executes a query.

## SQL templates

Where the change is applied through SQL, build statements from templates with **quoted, escaped
identifiers**. A crafted table, column or function name must not be able to alter the statement.
Test that explicitly with a name containing a quote and a semicolon.

## Tests

Under `backend/tests/`, at minimum:
- a table's row filter and column masks read back with function, input columns, types and owner;
- an ABAC-derived control is distinguished from a directly attached one and points at its policy;
- a function whose signature does not match the passed columns fails validation naming the argument;
- dropping a filter requires typed confirmation and the preview states what becomes visible;
- `impact.unknown` is populated when the audience cannot be enumerated;
- a crafted identifier cannot escape the SQL template;
- all four kinds return `MODE_READ_ONLY` under `connected_readonly`;
- a control that changed after preview is `PLAN_STALE`.

Use the fixture adapters. No network.
