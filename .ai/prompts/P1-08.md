## The flow

**1. Form.** Collects the change. Disabled while a request is in flight so a duplicate click is
impossible. Use react-hook-form with zod for **input** validation only; API types come from the
contract.

**2. Preview** renders the returned `Plan`:
- the normalized changes, with `description` prominent and `statement_preview` in a Details
  disclosure, never the other way round;
- `prerequisite_notes` shown plainly — a grant that will not work without `USE CATALOG` is a trap,
  and this is where the user must find out;
- `inheritance_note`;
- `impact.known` **and** `impact.unknown`. The unknown list is never hidden, never collapsed by
  default, and never omitted because it is empty-looking. If the app cannot compute who else is
  affected, the user must see that it could not;
- an identity block reading, in substance: you are requesting this change, and it will be executed
  by the application's service principal `{display}`;
- a live countdown to `expires_at`.

**3. Confirm.** A normal button, **unless** `requires_typed_confirmation`, in which case the user
must type `typed_confirmation_value` exactly, case-sensitive, before the control enables.

**4. Execute** via `POST /plans/{plan_id}/execute`. The result stays **in the page**. No toast as the
only feedback, no Undo, no optimistic update:
- **200 `applied`** — per-target rows, each with its `verified` badge and `summary`. `verified`
  means the state was read back; do not present an unverified success as verified.
- **200 `partially_applied` or `failed`** — per-target rows, failed ones showing `error.message`.
  Never summarize a partial failure as success.
- **202 `unknown`** — an "Outcome unknown" state with a **Check current state** button calling
  `reconcile`. Retry stays **disabled** until reconcile has returned. This is the most important
  branch in the component: a timeout does not mean failure, and retrying blindly could apply a
  change twice.
- **409** — map the code: `PLAN_STALE`, `PLAN_EXPIRED` or `PLAN_INVALIDATED` all render
  "Preview outdated — regenerate", **keeping the user's form values** so nothing is retyped;
  `DUPLICATE_OPERATION` fetches and shows the existing operation instead of executing again.

**5. Invalidation.** Editing principal, privileges or targets after a preview collapses the preview
and requires a new plan. A stale preview must never remain on screen next to edited inputs.

After an operation reaches a terminal status, invalidate the affected query keys so the grants table
reflects reality.
