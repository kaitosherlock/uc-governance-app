## The read operations available to you

```
GET /catalogs                                          listCatalogs
GET /catalogs/{catalog}/schemas                        listSchemas
GET /schemas/{catalog}/{schema}/objects                listSchemaObjects
GET /assets/{securable_type}/{full_name}               getAsset
GET /assets/{securable_type}/{full_name}/dependencies  getAssetDependencies
```

All five are implemented by the backend and work in fixture mode. `full_name` is ONE path segment
and `client.ts` already encodes it that way; do not encode it a second time.

## What to build

1. **Query hooks** in `src/api/queries.ts` for the five operations above, identity-scoped exactly
   like the existing hooks, passing the query's `AbortSignal` through to the client.

2. **Browse tree** — catalog, then schema, then object. The URL is the source of truth: the route
   `/assets/:catalog?/:schema?/:objectType?/:name?` already exists in `routes.tsx`. Selecting a node
   changes the URL; opening a URL directly restores the same view. Loading one level must not
   collapse or remount the levels above it.

3. **Search** across assets, debounced 300 ms, with the in-flight request cancelled through
   `AbortSignal` when the input changes again. An aborted request is not an error and must never
   render as one.

4. **Breadcrumbs** reflecting the current scope, every segment navigable.

5. **Asset overview** for the selected object: identity, owner, kind, comment, and whatever else the
   contract carries. Every fully-qualified name is monospace, middle-truncated, with the full value
   available on hover AND on keyboard focus, plus a copy button. Use `src/lib/fqn.ts`.

6. **Refresh** that refetches the current scope without a full page reload.

7. **All four states, everywhere, with stable layout and no jumps:**
   - Idle: no scope chosen yet — a purposeful empty state naming the next action.
   - Loading: a localized skeleton shaped like the final layout. Never a full-page spinner.
   - Error: the `ErrorResponse` mapped through `describeError`, with `next_steps` and the
     correlation id inside a `<details>`. A retry button is allowed here because these are reads.
   - Success: the data, plus `meta.limitations` rendered UNDER the data and never hidden. When
     `meta.completeness` is not `complete`, show a subtle notice.

   Empty success is NOT an error. Say "No objects visible to the application in this schema."
   together with the limitations. Never say "Nobody has access", "Secure", or "Compliant".

8. **`allowed_actions` gates every control.** `allowed: false` means the control is disabled AND its
   `reason` is visible — tooltip plus `aria-describedby`, never colour alone. When `navigate_to` is
   present, render a link instead.

9. Unknown enum values from the server render verbatim with an "Unknown" badge and never crash.

10. All user-visible text goes in `src/lib/strings.ts`. No English literal in a component.
