WHAT TO BUILD

1. `frontend/src/design/tokens.css`
   Implement the token system from docs/07 section 4 as CSS custom properties on `:root`, then a
   Tailwind v4 `@theme` block so the tokens are usable as utility classes. Cover:
   - An 11-step warm grey scale from paper `#FBFAF8` to ink `#1B1A17`.
   - Accent deep teal `#0F6E68`. Not purple.
   - Status colours: success `#1E7B4E`, warning `#9A6700`, danger `#B42318`, info `#3B5B7A`,
     unknown `#5F5A70`.
   - Spacing on a 4px base, radii 4px for controls and 6px for panels, exactly one elevation level.
   - A focus ring token: 2px accent with a 2px offset.
   - Motion tokens of 120ms and 160ms, wrapped so that a `prefers-reduced-motion: reduce` media
     query sets them to 0 and disables transitions.
   - Font families: one UI sans stack and one monospace stack for identifiers, with tabular
     numerals on the mono stack.

2. `frontend/src/index.css`
   Import Tailwind and `./design/tokens.css`. Set a base background and text colour from the
   tokens. Do not add decorative global styles.

3. `frontend/src/lib/strings.ts`
   Every user-visible string in the application, in English, as a single exported object organised
   by area: `nav`, `context`, `common`, `states`, `errors`. Include at minimum the navigation
   labels, the three mode labels exactly as the contract spells them, the executor sentence "You
   are requesting this change. It will be executed by the application's service principal {name}.",
   and empty, loading and error state text. No component may contain a hard-coded English sentence.

4. `frontend/src/lib/cn.ts`
   The standard `clsx` plus `tailwind-merge` helper.

5. `frontend/src/lib/fqn.ts`
   Helpers for fully qualified names: split a dotted name into parts, build a breadcrumb trail,
   middle-truncate a long name for display while keeping the full value for the title attribute,
   and encode a name for use as a single URL path segment.

6. `frontend/src/app/routes.tsx`
   React Router 8 routes using the data router API. The scope lives in the URL exactly as
   docs/02-architecture.md section 8 specifies:
   `/assets/:catalog?/:schema?/:objectType?/:name?` with a `tab` search parameter.
   Also route `/access`, `/policies`, `/activity`, `/platform`, and a catch-all not-found route.
   Every route renders a placeholder panel that names the task which will implement it. A
   placeholder must say plainly that the feature is not implemented yet. It must not pretend to
   show data.

7. `frontend/src/app/AppShell.tsx`
   The layout: a left rail, the context bar across the top, and a main content region.
   - The left rail groups navigation as docs/07 section 2 requires: Data Assets, Access Management,
     Policies, Activity, then a divider, then Platform. Use a real `<nav>` with a list, and mark the
     current route with `aria-current="page"`.
   - It collapses to icons below 1024px and the content region must not overflow horizontally at
     375px.
   - Skip-to-content link as the first focusable element.

8. `frontend/src/app/ContextBar.tsx`
   A presentational component taking `context: Context | null`, `identity: Identity | null` and
   `loading: boolean` as props. **No fetching in this task.** It renders:
   - The mode badge using `context.mode_label`, with a distinct icon per mode as well as colour,
     never colour alone.
   - The environment chip. Production must be distinguishable by text and a hatched border, not by
     colour alone.
   - The workspace host, the managed scope, the signed-in actor, and the execution identity shown
     as clearly separate items.
   - A loading skeleton with the same dimensions so the layout does not shift.

9. `frontend/src/app/providers.tsx`
   A single provider component. For now it only sets up the router. Do not add TanStack Query here;
   that belongs with the API client in P0-05.

10. `frontend/src/main.tsx` and `frontend/index.html`
    Standard Vite React entry. The document title is "Unity Catalog Governance". The html element
    has `lang="en"`.

11. `frontend/eslint.config.js`
    Flat config for eslint 9 wiring typescript-eslint, react-hooks and jsx-a11y with recommended
    rules, ignoring `dist` and `node_modules`. Keep it strict enough that an unlabelled control or
    a missing key fails lint.
