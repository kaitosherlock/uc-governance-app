ROLE: Backend Coder for the Unity Catalog Governance application.

TASK: P2-05 — dynamic views. Read a view's definition, and replace it as a plan kind.

The whole risk here is in one sentence of the spec: *manage supported dynamic views without
unintentionally overwriting their definitions.* A view definition is a single text blob. Replacing
it is destructive by nature, because whatever was there before is gone and this application has no
undo.

## Read

Return the view's current definition text, its owner, its dependencies, and whether it is a dynamic
view as opposed to an ordinary one. Where the SDK does not expose a field, say it is unavailable
rather than guessing.

## The replace plan kind

`replace_view_definition`, registered on the existing engine so it inherits HMAC binding, TTL,
observed-state hash, revalidation, verification and `MODE_READ_ONLY`.

Three things make this different from the other kinds and all three are required:

1. **A diff, not just the new text.** The preview must show what changes between the current
   definition and the proposed one, so the user can see what they are about to lose. A preview that
   only shows the new text invites someone to paste over a definition they never read.

2. **The observed-state hash must cover the definition text itself**, not the view's name or its
   metadata. If the definition moved between preview and execute — someone else edited it — that is
   `PLAN_STALE` and the change must be refused. This is the concrete mechanism that stops the
   unintentional overwrite the spec warns about, so make sure the handler observes the text.

3. **Typed confirmation**, because the change is destructive and not reversible by this application.

State in the preview that the application does not validate the new definition by running it. It has
not been parsed against a warehouse and it has not been executed. Say so rather than letting a clean
preview imply the SQL is correct.

## Tests

- a view read returns its definition, owner and dependencies, and distinguishes dynamic from
  ordinary;
- the preview contains a diff of old against new, not only the new text;
- a definition edited after preview produces `PLAN_STALE`;
- replace requires typed confirmation;
- the preview states that the definition was not executed or validated;
- a crafted view name cannot escape the SQL template;
- `MODE_READ_ONLY` under `connected_readonly`.

Use the fixture adapters. No network.
