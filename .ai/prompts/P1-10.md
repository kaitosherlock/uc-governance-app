## The three journeys

Write them as separate spec files under `frontend/e2e/`, named for what they prove.

**1. Find a table, read its access, grant a privilege, verify it.**
Browse or search to `sales.crm.orders`, open its Access tab, start a grant through the action
control, fill the form, and check the preview shows: the normalized change with its description
prominent, `statement_preview` only inside Details, `impact.unknown` visible without interaction,
and the identity block naming the executing service principal. Confirm, execute, and assert the
result panel appears **in the page** under its "Execution Outcome" heading with a per-target row and
its verified badge. Assert no toast is the only feedback and that no Undo is offered.

**2. Revoking an inherited grant sends you to the source.**
On the same Access tab, find a grant whose source is inherited. Assert its revoke control is **not**
an enabled button: it is disabled with its reason available to assistive technology, or it is a link
to the object where the grant actually lives. Follow that link and assert the app navigates to the
parent object's access view. This journey is the one that matters most — an app that appears to
revoke an inherited grant would tell someone access was removed when it was not.

**3. An unknown outcome is reconciled, not retried.**
Drive a grant whose execution returns HTTP 202 with `Operation.status === "unknown"`, using the
`?scenario=unknown-outcome` variant the handlers already support. Assert the outcome-unknown state
renders, that **Retry is disabled**, and that **Check current state** is the only forward action.
Click it, and assert the reconciled status replaces the unknown state. Assert the mutation was never
retried automatically.

## Rules for the specs themselves

- Address elements by **role and accessible name**, or by user-visible text from `strings.ts`. Never
  by CSS class, never by test id, never by DOM position. A journey that passes through the
  accessibility tree proves the feature is usable by everyone; one that passes through class names
  proves nothing and breaks on any restyle.
- Import user-facing strings from `@/lib/strings` rather than retyping them, so a copy change cannot
  silently orphan a test.
- No arbitrary sleeps. Wait for a condition.
- Each spec must be independent and must pass when run alone or in any order.
- Where a journey asserts an absence — no alert, no toast, no enabled retry — assert it after the
  state it belongs to has actually rendered, so the absence is meaningful rather than merely early.
