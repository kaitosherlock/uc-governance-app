## What each kind must do

**`grant`** — add privileges for a principal on the targets.
- Validate the principal exists and is UC-eligible. A workspace-local group is NOT UC-eligible;
  refuse it with the reason, do not silently skip it.
- Validate every privilege against the privilege catalogue **for that securable type**. A privilege
  that is not valid on the target type is a validation error naming both.
- A privilege the principal already holds directly is a no-op and must be shown as one in the
  preview rather than counted as a change.

**`revoke`** — remove privileges for a principal on the targets.
- **An inherited grant cannot be revoked at this level.** Refuse it with reason code
  `INHERITED_FROM_PARENT` and a `navigate_to` pointing at the object where the grant is actually
  held, exactly as the read path already does for `allowed_actions`. This is a correctness
  requirement, not a nicety: pretending to revoke an inherited grant would leave the user believing
  access was removed when it was not.
- Revoking a privilege the principal does not hold is a no-op, shown as one.

**`transfer_ownership`** — set a new owner.
- Ownership transfer is high-impact and irreversible by this app. It must set
  `requires_typed_confirmation` with `typed_confirmation_value` equal to the target's name, per the
  contract.
- Validate the new owner exists and is UC-eligible.
- The impact must say plainly what the current owner loses.

**`edit_metadata`** — comment, properties, column comments.
- Lowest risk of the four. Still goes through the full lifecycle; no shortcut path.

## Requirements that apply to all four

- **`prerequisite_notes`.** If a change needs something the user has not got — for example USE
  CATALOG and USE SCHEMA before a table-level SELECT is usable — say so in the preview. A grant that
  is technically applied but unusable without a prerequisite is a trap, and the preview is where it
  must be caught.
- **`inheritance_note`.** When a privilege at this level is inherited by children, say so.
- **`impact.known` and `impact.unknown`.** `unknown` is never empty for the sake of looking tidy and
  is never hidden. If you cannot compute an effect — for example who else is reached through group
  membership the app cannot read — it belongs in `unknown` with the reason.
- **`statement_preview`** on every `NormalizedChange`. It shows exactly what will be executed.
  Identifiers must be quoted and escaped so a crafted name cannot alter the statement; test that.
- **`description`** is the human sentence and is the prominent one; `statement_preview` is the
  detail.
- **Observe before and verify after** through the handler's `observe` and `verify`, so the engine's
  stale check and verification are real reads rather than assumptions. Where read-back genuinely
  cannot confirm a change, return the honest "cannot verify" signal rather than `True`.
- **Non-atomic multi-target execution** is already handled by the engine; do not add a transaction
  illusion on top of it.
- **Mode.** This deployment runs `connected_readonly`, where mutations must return `MODE_READ_ONLY`.
  Registering these kinds must not make a read-only deployment writable. Verify that with a test.

## Tests

Extend `backend/tests/`. At minimum:
- granting a privilege invalid for the securable type fails validation, naming privilege and type;
- granting to a workspace-local group is refused as not UC-eligible;
- revoking an inherited grant is refused with `INHERITED_FROM_PARENT` and a `navigate_to`;
- a no-op grant and a no-op revoke are shown as no-ops, not as changes;
- `transfer_ownership` requires typed confirmation and the value equals the target name;
- a crafted identifier cannot escape `statement_preview` quoting;
- prerequisite notes appear when a prerequisite is missing;
- `impact.unknown` is populated rather than empty when an effect cannot be computed;
- in `connected_readonly`, every one of the four returns `MODE_READ_ONLY`.

Use the fixture adapters. Do not reach the network.
